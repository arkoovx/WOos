# WoOS Development Plan

> Статус на 2026-10-30 (версия 1.41.0): базовый план (A–E), сетевой стек P1 (DNS, сокеты, WoOS Terminal), Single-Instance модель в планировщике, мгновенный рендеринг рамок окон и полноэкранный Maximize/Restore **успешно завершены**.

## 1) Пройденный этап (архив ключевых достижений)

Базовый фундамент и модули ядра полностью интегрированы:
- [x] Boot + long mode + формализованный staged init-flow (`early -> platform -> drivers -> ui`).
- [x] Базовые подсистемы: `pmm`, `kheap`, `idt`, `timer`, `mouse`, `pci`.
- [x] Вытесняющая многозадачность и планировщик Round-Robin с квантованием времени.
- [x] Защищённый режим Ring 3, аппаратный TSS, быстрые системные вызовы `syscall`/`sysret` и переключение CR3.
- [x] Интеграция внешней файловой системы FatFs (`external/fatfs`) с поддержкой FAT12/FAT32 и монтированием VFS.
- [x] Сетевой стек lwIP (`external/lwip`) с драйвером virtio-net, DHCP, UDP/TCP сокетами и WASM HTTP-сервером.
- [x] Интеграция WebAssembly-рантайма (`external/wasm3`) с мостом системных вызовов WASI (`wasi.c`).
- [x] Изолированный Ring 3 композитор (`COMPOSIT.WAS`) и оконный менеджер ядра с декорациями в стиле Windows (заголовок, рамка, кнопки закрытия/разворачивания/сворачивания, динамический таскбар, меню Пуск, предотвращение дублирования инстансов, 60+ FPS драг).
- [x] Первое полноценное прикладное WASM-приложение: калькулятор (`CALC.WAS`).

## 2) Архитектурные принципы WoOS

WoOS развивается по модели **"своё ядро + модульная архитектура без хардкода"**:
- **Никакого хардкода:** все таблицы окон, процессы, иконки и ресурсы опрашиваются динамически через системные вызовы.
- **Изоляция компонентов:** прикладной интерфейс и пользовательские программы работают в песочнице WebAssembly в Ring 3.
- **Производительность и отзывчивость:** строгий расчет dirty rectangles, локализованный VirtIO GPU flush и аппаратное отсечение (clipping).
- **Правило релизов:** каждый PR обновляет `VERSION`, `CHANGELOG.md` и проверяется тестами в QEMU.

## 3) Приоритеты дальнейшего развития

### P1. Системные приложения и пользовательское окружение (Application Suite)
- Расширение набора полезных WASM-приложений под Windows-подобный интерфейс:
  - **Блокнот / Текстовый просмотрщик (`NOTEPAD.WAS`):** открытие, просмотр и сохранение текстовых файлов с диска (VFS).
  - **Файловый менеджер (`EXPLORER.WAS`):** навигация по каталогам FAT12/FAT32, просмотр размеров файлов, запуск приложений.
  - **Системный терминал / Консоль (`CMD.WAS`):** интерактивная командная строка поверх WASI.
  - **Сетевая утилита (`FETCH.WAS` / `PING.WAS`):** загрузка данных по HTTP и сетевая диагностика.

### P2. Эволюция подсистемы памяти (Memory Stack & VMM)
- Согласно [`docs/MEMORY.md`](file:///home/arkoovx/Документы/WOos/docs/MEMORY.md):
  - **Этап M4 (Heap on PMM+VMM):** отвязка кучи ядра `kheap` от фиксированной арены 8 МБ, динамическое выделение виртуальных страниц по требованию через PMM.
  - **Этап M5 (MMIO Mapping Helpers):** централизованный helper для отображения MMIO/BAR регионов устройств.

### P3. Драйверный слой (Storage)
- Переход с legacy ATA PIO на поддержку современного контроллера AHCI (SATA) для высокой скорости чтения/записи блочных устройств.

## 4) Бэклог графических улучшений (отложено в конец плана)

### P4. Полноценная подсистема растровых ресурсов и масштабирования иконок
- **Декодер формата BMP (24-bit / 32-bit ARGB/BGR):** легковесный парсер Windows DIB/BMP без внешних зависимостей.
- **Пиксельный скейлер (Nearest-Neighbor / Bilinear Scaler):** алгоритм масштабирования растровых изображений с поддержкой альфа-канала и color-key прозрачности (например, `0xFF00FF`).
- **Инфраструктура ресурсов на диске:** чтение файлов иконок и фоновых изображений из каталога `/ICONS/` через стандартные вызовы VFS.
- **Динамическая привязка иконок:**
  - Каждый процесс/окно ассоциирует свою мастер-иконку (32×32 или 48×48).
  - Композитор автоматически масштабирует её для всех элементов системы: 48×48 на рабочий стол, 24×24 в меню «Пуск», 16×16 в заголовок окна и 16×16 на вкладку панели задач.
- **Обои рабочего стола (Wallpaper):** загрузка и отображение фонового изображения `/WALLPAP.BMP` вместо сплошной заливки.
